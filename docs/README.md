## 1. 优先级链（文档冲突时谁说了算）

```
① 代码与运行时的真实行为        （最高，实测永远赢）
② 决策记录.md 里最新的那条      （改主意了就追加一条，旧的作废）
③ 设计.md 的正文               （冻结后只追加变更记录）
④ 主题.md / 学习计划/…         （各自领域的细节）
⑤ 实施细节.md                  （可随时改的工具书）
⑥ 本文件                       （只是地图，不承载结论）
```

**任何文档里出现"与 XX 冲突"时，按上面这条链裁决，不要凭感觉。**

## 3. 三种读者的阅读路径

### A. 新会话 / AI 智能体接手（**按顺序读这五份**）

```
1. docs/README.md        ← 你在这
2. docs/项目状态.md       ← 现在到哪了、下一步是什么
3. docs/用户画像/技术水平.md ← 别用他做不到的方式讲话
4. docs/学习计划/进度.md   ← 他学到哪了
5. AGENTS.md             ← 环境、命令、已知坑（自动加载的那份）
```

再按需读 `设计.md`（要改功能时）、`决策记录.md`（要推翻旧结论时）、`主题.md`（要动样式时）。

### B. 作者自己找东西

- 想不起某个决定为什么这么做 → `决策记录.md` 搜关键词
- 忘了某个命令/配置 → `实施细节.md`
- 报错很眼熟 → `开发历程.md`

### C. 将来公开（博客/仓库首页）

`设计.md` 的 1、2、3 节 + `学习计划/00-总览.md` 可以直接搬上站——它们本来就是写给人看的，没有内部私密信息。**用户画像目录不要公开**（含设备与网络细节）。

## 5. 文档纪律与更新权限矩阵

### 5.1 权限矩阵（**谁改、什么时候改、能不能自动改**）

> 这张表是**授权书**。写在这里的"✅ 自动"意味着助手在对话中发现需要更新时，**直接改，不用问**，改完在回复里说一行"更新了 X：因为 Y"。

| 文件 | 自动更新 | 触发条件 | 硬约束 |
|---|---|---|---|
| `项目状态.md` | ✅ **必须** | 每次会话结束；阶段推进；出现/解除阻塞 | 只写"现在"，不许写历史 |
| `学习计划/进度.md` | ✅ **必须** | 每次汇报后；阶段开始时填日期 | **没做过的勾不许打** |
| `用户画像/技术水平.md` | ✅ **自动** | 每次汇报、每次暴露新能力/新缺口 | 只写事实与证据，带日期；不写评价 |
| `用户画像/偏好与协作.md` | ✅ 自动 | 发现新偏好或新雷区 | 新增要注明来源（哪句话/哪件事） |
| `用户画像/基本情况.md` | ✅ 自动 | 换机器、换环境、域名或网络变化 | 不放密码/密钥/token |
| `开发历程.md` | ✅ 自动 | 踩到一个新坑并解决 | **只追加**，不改旧条目 |
| `决策记录.md` | ✅ 自动 | 每谈定一个议题，或发现旧结论被推翻 | **只追加**，不改旧条目；推翻要写"取代第 X 条" |
| `实施细节.md` | ✅ 自动 | 写代码时发现细节与文档不符 | 与 `设计.md` 冲突时以设计为准 |
| `学习计划/00–04` | ⚠️ 条件 | 只在"计划需要变"时改（用了、卡住了、拆细了） | 改动必须在 `决策记录.md` 留一条 |
| `用户画像/目标与动机.md` | ⚠️ 条件 | **只在作者明确改变目标时** | 不许擅自调整优先级 |
| `主题.md` 的 **A–L 节** | ❌ **禁止** | 那是作者原文 | 只能追加 M 节之后的推导内容 |
| `设计.md` 正文 | ⚠️ 条件 | 只在该议题已谈定（有 D-xxx 记录）后改 | 必须同时写 `变更记录` 一行 |
| `README.md`（本文件） | ✅ 自动 | 新增/改名文档、结构变化 | 不改优先级链 |
| `AGENTS.md` | ⚠️ 条件 | 只在"稳定规矩"变化时 | 不写进度；改完必须在回复里说明 |

### 5.2 四条纪律

1. **状态与决策分开**：`项目状态.md` 写"现在"，`决策记录.md` 写"为什么"。**永远不要把"现在"写进决策记录**。
2. **只追加的文件不许回头改**：`决策记录.md`、`开发历程.md`、`主题.md` 的 A–L 节。
3. **每份文件头三行必须有**：用途、最后更新日期、可信度（草案/定稿/可改）。
4. **文档改动跟代码一起提交**：`docs: 更新项目状态到阶段 A 第 2 周`

### 5.3 助手的两条义务（写死，防止"以为记进去了其实没动"）

1. **改完必须报一行**：格式 `📄 已更新：文件 → 改了什么 → 为什么`。没报＝没改。
2. **该改没改也要说**：如果某次该更新但因为有硬约束不能改，明确说"这份我没动，因为 X，需要你确认"。

**反过来给你的检查办法**：任何一轮对话结束，如果你没看到 `📄 已更新` 那一行，那就真的没写进文件。
