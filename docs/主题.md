## D. 材质与光

| 项 | 你的答案 | 示例 |
|---|---|---|
| 主要材质 | 温润实木 + 细腻纸张 + 哑光黄铜 + 亚麻布艺/地毯 + 少量室内绿植 | 避免粗糙、破旧、剥落或冰冷金属感 |

## E. 排版

| 项 | 你的答案 |
|---|---|
| 标题字体感觉 | 优雅的现代衬线体（英文如 *Cormorant Garamond* / *Playfair Display*，中文如 *思源宋体* / *霞鹜文楷*），带古典书籍与建筑铭文气质 |

## F. 图形语言

| 元素 | 你想要的风格 |
|---|---|
| 图标 | 纤细优雅的线性图标（1.5px 描边，如 Lucide / Phosphor 风格），局部可带古典黄铜色点缀 |

| 空状态 | 一句温和的图书馆式提示（如“这层书架暂时空着，等以后慢慢填满”）+ 一个极简的茶杯或书签线稿 |
| 鼠标经过可点元素 | 3D 物件泛起柔和的琥珀色轮廓微光并浮出古典标签卡；静态卡片轻微上浮（`2px`）+ 边框转为黄铜色 |

## G. 动效

| 项 | 你的答案 | 备注 |
|---|---|---|
| 整体节奏 | 慢而舒缓、有温润阻尼感（`300ms - 500ms`，`cubic-bezier(0.22, 1, 0.36, 1)`） | 像推开厚重木门或翻动纸张，不急躁 |
| 页面进场 | 暖光渐显 + 场景元素与纸张卡片轻柔上浮淡入 | 模拟推门步入书房的瞬间 |
| 场景切换 | 点击具体功能时，3D 相机平滑推近/聚焦对应区域，同时纸张阅读面板自然展开覆盖（关闭时退回全景） | 保持空间连续性，避免生硬的白屏跳页 |
| 有没有"跟随鼠标"的效果 | 有极其克制的视差微动（鼠标移动时，俯视相机在极小角度内轻微偏移，增强空间纵深），并提供右上角“静止模式”开关 | 绝不大幅度晃动导致眩晕 |

| 问题 | 你的答案 |

| 场景里**有哪些实体**？（不是服务，是"东西"） | <br />这里的描述仅仅是书房一个场景的<br />1. 正上方居中：**古典大拱窗**（带窗帘与窗外庭院光影）；<br>2. 中景偏左：**温润木质书桌**（摊开的书本、台灯、茶杯、封装信笺盒、小型黄铜星象仪）；<br>3. 桌子右侧：**管理员艾米尔斯**（坐在椅子上安静看书/喝茶的风格化人物模型，不抢镜）；<br>4. 右侧靠墙：**高大古典木书架**（摆满书脊与小盆栽）；<br>5. 左半区与下半“后半区”：**木地板、古典花纹地毯与矮几**，作为静态网页元素的视觉承托基底 |

| 一共有几个区域/房间 | 主场景为 **1 个核心书房空间**，还有其他**n 个功能交互区**（藏书库：学习博客、奇物收藏室：随笔与收藏、借阅室：文件传输、Emils的私人实验室：其他网站访问、图书馆核心区：权限管理等管理员功能）我希望可以支持拓展（图书馆扩建） |

| 情况 | 你希望用户看到什么 |

## M2. 字体与字阶

```css
--font-serif: 'Cormorant Garamond', 'Source Han Serif SC', 'Noto Serif SC',
              'Songti SC', 'SimSun', serif;              /* 标题 */
--font-sans:  'Inter', -apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif;  /* 正文 */
--font-mono:  'JetBrains Mono', 'SF Mono', Consolas, monospace;
```

**中文衬线 web 字体的硬约束**：思源宋体完整包 5–8 MB，直接引会让首屏崩。做法是**只对标题用到的字做子集化 woff2**（一个站标题字符集通常 200–400 字，压到 60–120 KB）。正文一律用系统无衬线，不下载字体。

字阶（`clamp`，字距随时间/数字用 `tabular-nums`）：

```css
--text-xs:   0.8125rem;
--text-sm:   0.9375rem;
--text-base: 1rem;
--text-lg:   clamp(1.125rem, 1rem + 0.5vw, 1.375rem);
```

## M5. 场景锚点与 DOM 对齐（这一节决定"静态元素融入场景"能不能成立）

**做法**：不要试图把 HTML 塞进 3D 里，而是**把 3D 世界坐标投影成屏幕坐标，再把 DOM 绝对定位到那儿**。

1. `try/scene-fix/pipeline/render_box.py` 增加一个导出：把每个物件的世界坐标与朝向写进 `scene-anchors.json`
2. 前端用**同一套相机参数**（`pos / yaw / pitch / hfov`）做针孔投影，得到屏幕像素位置
3. DOM 卡片用 `position: absolute` + `transform: rotate() scale()` 贴上去，朝向由锚点法线算出
4. 视差：背景图与 DOM 层施加**同一个位移量**，所以不需要每帧重投影

```json
{
  "camera": { "pos": [3.62, 2.46, 5.72], "yaw": 0.0, "pitch": -30.0, "hfov": 63.0, "aspect": 1.7768 },
  "room":   { "w": 7.0, "d": 4.8, "h": 3.05 },
  "anchors": {
    "desk-surface": { "world": [0.20, 0.78, 0.40], "normal": [0, 1, 0], "size": [1.6, 0.9] },
    "bookshelf":    { "world": [-1.80, 1.60, -2.30], "normal": [0, 0, 1], "size": [1.2, 1.8] },
    "character":    { "world": [1.55, 0.55, 0.90],  "normal": [0, 0, 1], "size": [0.6, 1.1] },
    "window":       { "world": [-1.20, 2.10, -2.38],"normal": [0, 0, 1], "size": [1.8, 1.0] },
    "rug-center":   { "world": [0.00, 0.01, 1.20],  "normal": [0, 1, 0], "size": [2.4, 1.6] }
  }
}
```

**为什么这条重要**：相机是固定机位（只有微小视差），所以锚点投影只在**断点变化时算一次**，不是每帧算。V1 用预渲染静帧、V2 换 WebGL 实时渲染，**都用同一个 `scene-anchors.json` 和同一套投影公式，DOM 层一行都不用改**。

## M6. 响应式与降级矩阵

| 场景 | 处理 |
|---|---|
| ≥1280px 桌面 | 静帧/WebGL 场景 + DOM 投影卡片 + 鼠标视差 |
| 768–1279px | 同一场景，卡片改为按锚点归组为 2 列，减少重叠 |
| <768px 手机 | 关掉 3D/静帧铺满，改为"上方卡片流 + 下方裁切静帧"，`scene-anchors` 不参与布局 |
| 无 WebGL / 加载失败 | 静帧兜底（V1 本来就全是静帧，天然达标） |
| `prefers-reduced-motion` | 无视差、无光尘、无相机推拉，交叉淡入 |
| 搜索引擎 / 无 JS | 完整语义 HTML：导航、文章列表、正文全部可读 |
