## 3. 学习方式：三遍法

**每个知识点必须走三遍，少一遍就不算会：**

| 遍 | 做什么 | 判据 |
|---|---|---|
| **1 看懂** | 看视频/文档，**不动手** | 能用自己的话讲出它在解决什么问题 |
| **2 改坏再修好** | 把示例代码故意改错 3 处，看报错长什么样 | 能从报错信息定位到出错的那一行 |
| **3 自己重写** | 关掉教程，从空白文件重写一次 | 卡住时只查文档、不翻视频 |

**第 3 遍是唯一有效的。** 只看不做会在两周内全部忘光，这是所有人学编程最常见的失败方式。

## 4. 每个阶段的固定节奏

```
① 我写详细清单（看哪几节、练什么、判据是什么）
② 你学 + 写，卡住超过 40 分钟就按下面"卡住了怎么办"处理
③ 阶段结束时你汇报（模板见第 6 节）
④ 我验收：看代码 + 问 3 个问题（答不上就是没过），然后写下一阶段
```

### 卡住超过 40 分钟怎么办（三步）

1. **缩到 10 行以内能复现**——90% 的问题在缩小过程中自己就暴露了
2. **把报错原文贴进搜索**（不是描述，是原文）
3. **还不行就贴给我**：报错原文 + 完整代码 + 你以为是哪一行出问题

⚠️ **不许做**：不看报错就改代码试运气、把整个文件贴给别人让改、跳过练习看下一个视频。

我会用三个问题验收：

1. 这段代码删掉会怎样？
2. 如果需求改成 X，你要改哪一行？
3. 你卡在哪里，最后是怎么解决的？

答不上来就说明是"抄过去的"，不是"学会了"——那就重做第 3 遍。

## 7. 技术栈全表（附"为什么要学它"）

## 8. 明确不学（避免贪多）

| 不学 | 理由 |
|---|---|
| Vue / Angular | 项目用 React，学两套框架只会混淆 |
| Webpack | Vite 已经封装好了，等需要自定义构建再看 |
| 微服务 / Kubernetes | 单机项目用不上，实习前再补概念 |
| Tailwind | 你的主题需要精细控制，手写 CSS 更合适 |
| Redux / Zustand | 项目状态简单，TanStack Query + useState 够 |
| Electron / React Native | 与本项目无关 |
| 算法刷题 | 和实习准备冲突时再单独排，不混进这个计划 |
