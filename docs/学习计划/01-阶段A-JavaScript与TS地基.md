### 练习 2（本周主体产出）

做一个"文章列表"页面，要求：

1. 数据写在一个 TS 数组里（3–5 条：标题、日期、标签、简介）
2. JS 动态生成卡片（**不许用 `innerHTML` 拼字符串**，用 `document.createElement` + `textContent`）
3. 鼠标移上去卡片高亮（用 `classList`，不用 `style`）
4. 点击卡片展开简介，再点收起
5. 顶部有一个标签筛选（点"全部/随笔/笔记"切换显示）

**判据**：
- 把一条数据的标题改成 `<img src=x onerror=alert(1)>`，页面上应该**原样显示这串字**，不弹窗。这证明你用的是 `textContent` 而不是 `innerHTML`——这条就是你以后写评论系统时要靠的直觉。
- 打开 DevTools 的 Elements 面板，能看到你生成的 DOM 结构。

### 3.3 练习 4：2D 投影雏形（对应项目里的锚点对齐）

这是**唯一一个"数学练习"**，但只有 20 行，而且它就是你以后 3D 投影的一维简化版。

要求：

1. 定义 5 个点 `{ x: number, y: number }`（坐标范围 0–1）
2. 写一个函数 `toScreen(p, viewWidth, viewHeight)`，把 0–1 的坐标映射成屏幕像素
3. 写第二个函数 `withParallax(p, dx, dy)`，把所有点整体平移 `dx, dy` 像素

> 这个练习做完，你就理解了 `docs/主题.md` M5 节那套"锚点投影"的核心——3D 只是多了一个 z 轴和一个除法。

## 8. A-4 · CSS 排错微模块（穿插在第 2、3 周，共约 4 小时）

> 作者自评："CSS 会写但很丑，容易出错，出错时说不清为什么。"
> 这四条是补齐这个短板的最小集。**不做完不算通过 A 阶段。**

### 8.1 DevTools 布局排查（1 小时）

| 要会的 | 怎么练 |
|---|---|
| 盒模型高亮 | Elements 面板选中元素，看橙色（margin）/ 绿色（padding）/ 蓝色（content）三块 |
| `computed` 面板 | 能查出某个元素最终的 `width` 到底是谁算出来的 |
| 临时调试边框 | 在 Styles 里加 `outline: 1px solid red`（**用 outline 不用 border**，outline 不占布局） |
| 关掉某条规则 | 勾选框取消/恢复，观察页面变化——这是判断"这条规则到底管什么"最快的办法 |

### 8.2 五种常见故障（2 小时）

每一种都手动复现一次，再修好，写下"现象 → 原因 → 修法"：

1. **margin 塌陷**：父子元素的外边距合并，导致间距比预期小
2. **溢出**：内容超出容器，出现横向滚动条（`overflow-x` 排查法）
3. **高度算不准**：flex 子项被内容撑高 / 被压缩（`min-height: 0` 的问题）
4. **绝对定位参照错**：`position: absolute` 的父元素没有 `position: relative`
5. **z-index 失效**：父元素建立了新的层叠上下文，子元素怎么调都盖不上去

### 8.3 判断"好不好看"的三个数字（0.5 小时）

| 判据 | 达标线 | 怎么测 |
|---|---|---|
| 正文对比度 | ≥ 7:1（次要文字 ≥ 4.5:1） | DevTools 取色器直接显示比值 |
| 间距是否成体系 | 所有间距落在 4/8/12/16/24/32/48/64/96 这九档 | 手动量一遍，出现 13px、17px 就是没成体系 |
| 行长 | 正文 ≤ 64 个字符宽 | 给段落加 `max-width: 64ch` 前后对比 |

### 8.4 自查一次（0.5 小时）

拿练习 2 的页面：

1. 截一张图
2. 用红笔（或文字）标出 **3 处自己不满意的地方**
3. 每处写出：**它违反了上面哪条判据**，以及"我想让它变成什么样"

> 这一步是整份学习计划里唯一练"审美判断"的地方。说不清哪里丑，就永远改不好。
