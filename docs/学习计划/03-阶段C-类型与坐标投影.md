## 2. 第二周：坐标投影（项目里最"技术"的一块）

### 2.1 要懂的原理（只有这么多）

你有一个三维点 `(x, y, z)`，相机在某个位置、朝向某个方向、有一定的视野角。要算出它在屏幕上落在第几个像素。三步：

```
① 把世界坐标变换到相机坐标系（平移 + 按 yaw/pitch 旋转）
② 透视除法：screenX ∝ x / z，screenY ∝ y / z   ← 越远越小
③ 把 -1..1 的归一化坐标映射到 0..width / 0..height
```

**你不需要手推矩阵**。你需要能解释两件事：

- 为什么除以 `z`：因为远处的物体在视网膜上投影更小
- 为什么视野角（fov）决定"看起来多广"：`焦距 = 屏幕宽度 / (2 × tan(fov/2))`

### 2.2 练习 C2：写 `projectAnchor`

在 `src/lib/projection.ts` 里实现：

```ts
export interface Camera {
  pos: [number, number, number]
  yaw: number      // 度
  pitch: number    // 度
  hfov: number     // 水平视野角
}

export interface Anchor {
  world: [number, number, number]
  normal: [number, number, number]
  size: [number, number]
}

export function projectAnchor(a: Anchor, cam: Camera, view: { w: number; h: number }):
  { x: number; y: number; scale: number; rotate: number } | null
```

返回值里 `null` 表示这个点在相机背后（`z <= 0`），不该显示。

**必须写单元测试**（用 vitest），至少 4 个用例：

| 用例 | 期望 |
|---|---|
| 锚点在相机正前方 | 落在屏幕中心附近 |
| 锚点在相机背后 | 返回 `null` |
| 视野角变大 | 同一个点离中心更近（画面更广） |
| 视图尺寸翻倍 | 像素坐标翻倍，但归一化位置不变 |

运行：`npx vitest`。判据：4 个用例全绿。

### 2.3 换成真投影

把 B 阶段的百分比坐标替换掉：

| 改之前 | 改之后 |
|---|---|
| `study.anchors.ts` 里写 `{ x: 22, y: 58 }` | 写 `{ world: [0.2, 0.78, 0.4], normal: [0,1,0], size: [1.6,0.9] }` |
| `AnchorCard` 直接 `left: 22%; top: 58%` | `AnchorCard` 调 `projectAnchor()` 得到 px，再 `left: ${x}px` |

`AnchorCard` 的**外部接口不变**（还是接收一个 anchor），所以其它代码一行不用改——这就是 B 阶段先用百分比的收益。

判据：把浏览器窗口从 1280 拖到 1920，卡片**始终贴在桌面的同一块木板上**（不是漂移）。

### 2.4 视差怎么办

视差时整层位移，但**锚点也要跟着动**，否则卡片会和背景错位。

做法：视差量 `dx, dy` 是像素级的（±2px），直接把它加到投影结果的 `x, y` 上即可。近似足够，不需要重算相机。

## 3. 第三周：场景注册表 + 路由 + 部署

### 3.1 场景注册表

用 Vite 的 `import.meta.glob` 自动收集 `scenes/` 下所有 `manifest.json`：

```ts
// src/scenes/registry.ts
const modules = import.meta.glob('./*/manifest.json', { eager: true })
export const scenes = Object.fromEntries(
  Object.entries(modules).map(([path, mod]) => {
    const id = path.split('/')[1]
    return [id, (mod as { default: SceneManifest }).default]
  })
)
```

判据：**新建一个 `scenes/test/manifest.json` 目录，不改任何代码，路由 `/explore/test` 就能打开**。这条判据就是"可扩展"的定义。

### 3.2 路由（react-router v7）

| 路径 | 组件 | 加载方式 |
|---|---|---|
| `/explore/:sceneId` | `SceneView` | 同步（首屏就是它） |
| `/blog/:slug` | `BlogPost` | `React.lazy` |
| `/login` | `Login` | `React.lazy` |
| `/admin/*` | AdminLayout 及其子页 | `React.lazy`（整个目录） |

练习 C3：做**结构图场景**（L2）。一张俯视图 + 5 个热区，点热区跳到对应场景。热区用百分比即可，不需要投影。

### 3.3 部署到子域（只学最小路径）

这一步需要你在云上操作。**只学最小集**，深入的放到 F 阶段：

| 步骤 | 命令/操作 | 判据 |
|---|---|---|
| 1. 加 DNS 记录 | 域名商后台：`new` → A → `82.157.154.188` | `dig +short new.justinemils.top` 有结果 |
| 2. 本地构建 | `npm run build` | `dist/` 生成 |
| 3. 传文件 | `rsync -avz --delete dist/ user@82.157.154.188:/var/www/selfwebsite/dist/` | 云上目录有 index.html |
| 4. 加 nginx server 块 | `server_name new.justinemils.top;` + `root` 指向上面的目录 | `curl -I http://new.justinemils.top` 返回 200 |
| 5. 扩证书 | `certbot --nginx -d new.justinemils.top` | 浏览器地址栏有锁 |
| 6. 验证 | `curl -I https://new.justinemils.top` | 200 + HSTS 头 |

⚠️ 现有的 `justinemils.top` 在 443 跳 `8443`，**不要动它的配置**。新子域用独立的 server 块。

练习 C4：写一个 `deploy.sh`，把第 2–3 步串起来。判据：以后发版只跑这一条命令。
