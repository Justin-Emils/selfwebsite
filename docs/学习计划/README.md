## 使用规则

1. **计划可以改，进度必须真实。** `进度.md` 里没打勾就是没做过，不许"差不多算完成"。
2. **每完成一个阶段，用 `00-总览.md` 第 6 节的模板汇报**，助手据此写下一阶段的详细修订版。
3. **阶段内部允许延期 50%**；超出就说明切得太粗，拆细。
4. **不要跳阶段。** C 阶段依赖 A 阶段的投影练习，D 阶段依赖 C 阶段的路由与接口约定。

## 什么时候汇报（2026-11-23 定）

汇报不是"学完才说"，按这五个触发器走：

| 触发器 | 汇报形式 | 内容 |
|---|---|---|
| 完成**一个练习** | 轻量（3 行） | 做了什么 / 卡在哪 / 用时 |
| 完成**一个子阶段**（A-1/A-2/A-3/A-4） | **完整模板**（`00-总览.md` 第 6 节） | 勾选清单 + 报错原文 + 三问自答 |
| 卡住**超过 40 分钟** | 立即求助 | 报错原文 + 完整代码 + 你以为是哪一行 |
| **每次会话结束** | 一句话 | 这轮做了什么；助手据此更新 `进度.md` 与 `项目状态.md` |
| 连续 **2 周没进展** | 停下来聊 | 是计划切得太粗，还是别的原因 |

**不需要每天汇报。** 但有一条硬规矩：**`进度.md` 里没勾 = 没做过**，不存在"差不多算完成"。

**汇报的判据是"有代码可看"，不是"看完了视频"。**
