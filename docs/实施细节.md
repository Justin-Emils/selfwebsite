## 0. 一句话定位

**一个域名下同时提供：公开展示的名片、可读可写的博客、自用的服务门户与服务器控制台。**

这不是静态单页，是一个单人全栈应用。它的第一目的不是上线，是**练会开发**——具体说，是为明年 agent 全栈开发实习准备一个能拿得出手、又能日常使用的真实项目。

---

## 1. 三个面，一条铁律

| 面 | 内容 | 谁看 | 鉴权 | 进首屏 bundle |
|---|---|---|---|---|
| **展示面** | 六区：Hero / About / Awards / Stack / Hobbies / Contact | 任何人 | 无 | 是（性能预算最严） |
| **博客面** | 读（公开）/ 写（私有，站内编辑器） | 读：任何人；写：只有我 | 读否 / 写是 | 读写分离，写侧全 lazy |
| **控制台** | 服务门户、主机监控、白名单动作、审计日志 | 只有我 | 是（密码 + TOTP） | **绝不** |

**铁律：控制台的任何代码、依赖、请求都不得出现在展示面的加载路径上。**

理由不是洁癖，是攻击面隔离：展示面是公网无鉴权入口，控制台是提权入口。两者共用一次构建、共用一份 JS 时，一个后台依赖的漏洞（编辑器、图表库、上传组件）就会变成前台的可利用点；而且后台每改一行，公开展示面都得跟着重新部署。

实现手段（三条，都是硬性的）：

1. `/admin/*` 全部路由 `React.lazy` 加载，物理上落进独立 chunk。
2. 后台依赖（CodeMirror、图表库、上传组件）只在 `routes/admin/` 里 import，`routes/` 其他文件 import 它们即视为设计违规。
3. API 侧 `Depends(require_user)` 一律显式声明，不做"全局中间件白名单 + 例外"那种反向写法。

## 2. 物理拓扑

### 2.1 三台机器

| 机器 | 位置 | 角色 | 跑什么 | 不跑什么 |
|---|---|---|---|---|
| **腾讯云服务器**（跳板） | 公网，有固定 IP | 公网入口 | Nginx、certbot、WireGuard 服务端 | 数据库、用户上传、业务逻辑 |
| **计算服务器** | 工作室内网（NAT 后） | 应用主机 | FastAPI、SQLite、Alembic、定时任务、（可选）本地 LLM | 公网监听 |
| **存储服务器** | 工作室内网（现为 `192.168.1.112`，CIFS 导出） | 数据主机 | NFS/CIFS 导出：`uploads/`、`backups/`、文章源文件快照 | **数据库**、代码仓库、venv/node_modules |

### 2.2 数据流向

```
浏览器
  │ HTTPS 443
  ▼
腾讯云 Nginx ──── /            → /var/www/selfwebsite/dist（静态，长缓存）
  │              ──── /media/*   → 反代到内网 API（或由 API 直出）
  │              ──── /api/*     → 反代 10.8.0.2:8000（WireGuard 隧道）
  │
  │ WireGuard（仅此一条入口，无端口暴露）
  ▼
计算服务器 FastAPI:8000（只听 10.8.0.2）
  ├─ SQLite  → /srv/selfwebsite/data/app.db（**本地盘**）
  ├─ uploads → /mnt/storage/selfwebsite/uploads（NFS/CIFS 挂载）
  └─ 只读采集 psutil / systemctl / docker stats
```

### 2.3 三条硬约束（踩过或即将踩的坑）

| 约束 | 为什么 |
|---|---|
| **SQLite 文件必须在本地盘** | WAL 模式依赖共享内存与文件锁；跨 NFS/CIFS 会锁失效 → 数据库损坏。这是设计禁区，不是性能建议 |
| **代码仓库、venv、node_modules 不得在网络盘** | AGENTS.md 第 8 节已实证：CIFS 上 `chmod`、`ln -s`、`fs.copyFileSync` 全部失败 |
| **媒体目录可以放网络盘** | 媒体是「一次写入、多次读取、不 chmod」的不可变文件，跨网络只读访问没问题；写入走 API 单进程，不需要并发锁 |

### 2.4 降级与可用性

家里断网 = 博客 API 挂。这不是要消灭的问题，是要**设计出降级路径**：

| 故障 | 影响 | 降级 |
|---|---|---|
| 工作室断网 / 计算服务器关机 | 博客、控制台 502 | 展示面静态托管在腾讯云，**永不挂**；博客详情页可预渲染成静态 HTML 兜底（P5 可选） |
| WireGuard 隧道断 | 同上 | systemd 自动重连 + 腾讯云 Nginx 返回维护页 |
| 存储服务器挂 | 上传失败、图片 404 | API 启动时检查挂载点，缺失则拒绝上传并亮红灯（健康检查里体现） |

## 4. 仓库与目录结构

### 4.1 决策：前端留根目录，后端放 `api/`

不迁 `apps/web`。理由：AGENTS.md 第 3 节明令「不要反复重构脚手架」，而 `apps/web` 迁移要动 tsconfig / eslint / vite 路径，收益是"看起来更专业"，成本是半天折腾加一次高风险提交。

**升级触发条件**（满足任一再拆成 `apps/web` + `apps/api` + `packages/`）：

- `routes/admin` chunk > 300 kB（gzip）
- 后端需要独立部署节奏（例如一台上跑两个 API）
- 出现第二个前端（例如给控制台单独做移动端壳）

## 5. 数据模型

### 5.1 定稿 DDL

```sql
-- SQLite 连接初始化（每次连接执行）
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA synchronous = NORMAL;

-- ── 账号与会话 ──
CREATE TABLE users (
  id            INTEGER PRIMARY KEY,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,              -- argon2id
  totp_secret   TEXT,                       -- base32，未启用时为空
  totp_enabled  INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE sessions (
  id           TEXT PRIMARY KEY,             -- 随机 32 字节的 sha256 十六进制；原始 token 只存在 cookie 里
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  last_seen_at TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at   TEXT NOT NULL,
  ip           TEXT,
  user_agent   TEXT
);
CREATE INDEX idx_sessions_user    ON sessions(user_id);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);

-- ── 媒体 ──
CREATE TABLE media (
  id         INTEGER PRIMARY KEY,
  filename   TEXT NOT NULL UNIQUE,           -- 落盘名（uuid.webp），原始名另存
  orig_name  TEXT NOT NULL,
  mime       TEXT NOT NULL,                  -- 规范化后只会有 image/webp 等白名单值
  size       INTEGER NOT NULL,
  width      INTEGER,
  height     INTEGER,
  sha256     TEXT NOT NULL,                  -- 去重 + 完整性
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- ── 博客 ──
CREATE TABLE posts (
  id           INTEGER PRIMARY KEY,
  slug         TEXT NOT NULL UNIQUE,
  title        TEXT NOT NULL,
  summary      TEXT NOT NULL DEFAULT '',
  cover_id     INTEGER REFERENCES media(id) ON DELETE SET NULL,
  status       TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','published')),
  published_at TEXT,
  content_md   TEXT NOT NULL DEFAULT '',
  html_cache   TEXT,                         -- 渲染 + 消毒后的 HTML
  toc_json     TEXT,                         -- [{depth,text,id}]
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at   TEXT
);
CREATE INDEX idx_posts_pub ON posts(status, published_at DESC) WHERE deleted_at IS NULL;

CREATE TABLE post_revisions (
  id         INTEGER PRIMARY KEY,
  post_id    INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  content_md TEXT NOT NULL,
  title      TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_rev_post ON post_revisions(post_id, created_at DESC);

CREATE TABLE tags (
  id   INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  slug TEXT NOT NULL UNIQUE
);

CREATE TABLE post_tags (
  post_id INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  tag_id  INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (post_id, tag_id)
);

-- 全文搜索（P5）
-- 注意：中文不能用 unicode61（它会把整段中文当成一个 token，搜不出来）。
-- trigram 按 3 字符滑窗切分，对中英文子串匹配都有效；代价是索引体积大一些。
CREATE VIRTUAL TABLE posts_fts USING fts5(
  title, summary, content_md,
  content='posts', content_rowid='id',
  tokenize='trigram'
);

-- ── 门户与控制台 ──
CREATE TABLE services (
  id           INTEGER PRIMARY KEY,
  name         TEXT NOT NULL,
  description  TEXT NOT NULL DEFAULT '',
  icon         TEXT,                          -- media.filename 或 emoji
  url_public   TEXT,
  url_internal TEXT,
  health_url   TEXT,                          -- 可选，探活用
  sort_order   INTEGER NOT NULL DEFAULT 0,
  visible      INTEGER NOT NULL DEFAULT 1,    -- 0 = 只在控制台可见（内网服务）
  created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE hosts (
  id         INTEGER PRIMARY KEY,
  name       TEXT NOT NULL,
  kind       TEXT NOT NULL CHECK (kind IN ('local','agent')), -- local = API 所在机；agent = 内网小 agent
  address    TEXT NOT NULL,                   -- local 填 127.0.0.1；agent 填 http://ip:port
  token      TEXT,                            -- agent 鉴权
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE metrics (
  id         INTEGER PRIMARY KEY,
  host_id    INTEGER NOT NULL REFERENCES hosts(id) ON DELETE CASCADE,
  ts         TEXT NOT NULL,
  cpu_pct    REAL,
  mem_used   INTEGER, mem_total INTEGER,
  disk_used  INTEGER, disk_total INTEGER,
  load1      REAL,
  uptime_sec INTEGER
);
CREATE INDEX idx_metrics_host_ts ON metrics(host_id, ts DESC);

CREATE TABLE actions (
  id       INTEGER PRIMARY KEY,
  name     TEXT NOT NULL UNIQUE,             -- 路由里引用的 key，如 restart-nginx
  label    TEXT NOT NULL,                    -- 按钮文案
  kind     TEXT NOT NULL CHECK (kind IN ('systemctl','deploy','docker','script')),
  target   TEXT NOT NULL,                    -- 单元名 / 容器名 / 脚本路径
  args_json TEXT NOT NULL DEFAULT '[]',      -- 固定参数，不接受前端传参
  confirm  INTEGER NOT NULL DEFAULT 1,       -- 二次确认
  enabled  INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE audit_log (
  id        INTEGER PRIMARY KEY,
  ts        TEXT NOT NULL DEFAULT (datetime('now')),
  user_id   INTEGER REFERENCES users(id) ON DELETE SET NULL,
  action_id INTEGER REFERENCES actions(id) ON DELETE SET NULL,
  params    TEXT,
  ip        TEXT,
  ok        INTEGER NOT NULL,
  output    TEXT                             -- stdout/stderr 尾部 4KB
);
CREATE INDEX idx_audit_ts ON audit_log(ts DESC);

-- ── 站点设置（键值，避免为每个开关加列）──
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

### 5.2 数据保留策略

| 表 | 策略 |
|---|---|
| `metrics` | 原始数据保 7 天，每小时聚合一行保 1 年（APScheduler 每日 03:00 跑压缩） |
| `sessions` | 过期即删（每日清理），保留最近 30 天登录记录 |
| `post_revisions` | 每篇文章保最近 50 版，更早的归档到存储服务器 |
| `audit_log` | 不删。体积小，是唯一的操作追溯 |
| `media` | 删除时先软标记，30 天后真删文件（避免文章引用断图） |

### 5.3 备份

| 对象 | 方式 | 频率 | 保留 |
|---|---|---|---|
| `app.db` | `sqlite3 app.db ".backup /mnt/storage/backup/app-$(date +%F-%H%M).db"` | 每 6 小时 | 30 份 |
| `uploads/` | 反向 rsync 到存储服务器第二目录 | 每日 | 快照 7 份 |
| `posts` 源文件 | 每篇发布时同步一份 md 到存储服务器（正文的纯文本副本） | 发布时 | 全量 |
| 代码 | git + GitHub 远端 | 每次提交 | 全量 |

**可验证判据**：任一时刻，删掉计算服务器上所有数据，能凭存储服务器备份 + GitHub 在 1 小时内恢复站点。

## 6. API 契约

统一前缀 `/api`。除标注 `公开` 外全部需要有效 session，未登录返回 `401 {"detail":"unauthorized"}`。

### 6.1 认证

| 方法 | 路径 | 鉴权 | 入参 | 出参 |
|---|---|---|---|---|
| POST | `/auth/login` | 公开 | `{username, password, totp?}` | `204` + `Set-Cookie: sid=...; HttpOnly; Secure; SameSite=Strict; Path=/` |
| POST | `/auth/logout` | ✅ | — | `204`，删 session |
| GET | `/auth/me` | ✅ | — | `{id, username, totp_enabled}` |
| POST | `/auth/totp/setup` | ✅ | — | `{secret, otpauth_url}`（未启用时） |
| POST | `/auth/totp/enable` | ✅ | `{code}` | `204` |
| POST | `/auth/sessions/revoke-all` | ✅ | — | `204` |

错误码约定：密码错 `401`；需要 TOTP 但未提供 `401 {"detail":"totp_required"}`；触发限速 `429`；账号锁定 `423`。

### 6.2 博客 · 公开

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| GET | `/posts` | `?tag=&cursor=&limit=10` | `{items:[{slug,title,summary,published_at,tags,cover}], next_cursor}` |
| GET | `/posts/{slug}` | — | `{slug,title,summary,published_at,updated_at,tags,html,toc,prev,next}` |
| GET | `/tags` | — | `[{name,slug,count}]` |

- 所有写接口返回的 `updated_at` 供前端做乐观更新校验。

## 7. 认证与权限设计

### 7.1 登录流程

```
① POST /auth/login {username, password}
   → argon2 校验；失败计数 +1（Redis 无，用内存 + DB）
② 若 totp_enabled：返回 401 {"detail":"totp_required"}，前端切到二次输入
③ POST /auth/login {username, password, totp}
   → pyotp 校验（±1 个 30s 窗口容错）
   → 生成 32 字节随机 token，DB 存 sha256(token)，cookie 存原文
   → 失败计数清零
```

### 7.2 会话

| 项 | 值 |
|---|---|
| Cookie | `sid`，`HttpOnly; Secure; SameSite=Strict; Path=/` |
| 有效期 | 7 天滑动（每次请求 `last_seen_at` 刷新，超 7 天未用即失效） |
| 存库形式 | 只存 `sha256(token)`。数据库泄露也拿不到可用 cookie |
| 并发 | 允许多设备同时在线，控制台显示「当前会话列表」可单独踢 |
| 登出 | 删当前 session；「全部登出」删该用户所有 session |

### 7.3 防暴力破解（三层）

1. **slowapi 限速**：`/auth/login` 5 次/分钟/IP，超出 `429`。
2. **账号级锁定**：连续失败 10 次锁 15 分钟（`423`），成功即清零。
3. **fail2ban**（腾讯云侧）：Nginx 日志里 `429`/`423` 反复出现 → 封 IP 1 小时。

### 7.4 CSRF

`SameSite=Strict` 已挡住绝大多数场景。补两道：

- 所有状态变更接口校验 `Origin`/`Referer` 必须是本站域名。
- 前端 `fetch` 统一带 `X-Requested-With: selfwebsite`，中间件校验（简单，且对表单自动提交类 CSRF 有效）。

### 7.5 真实 IP

API 在 WireGuard 后面，必须显式信任代理，否则限速会按 `10.8.0.x` 全站共用一个桶：

- Nginx：`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` + `proxy_set_header X-Forwarded-Proto $scheme;`
- Uvicorn：`--proxy-headers --forwarded-allow-ips=10.8.0.1`

## 8. 博客子系统

### 8.1 存储形态：md 是唯一真相

| 层 | 存什么 | 在哪 |
|---|---|---|
| 正文 | Markdown 原文 | `posts.content_md` + 发布时同步一份 `.md` 到存储服务器 |
| 渲染结果 | HTML（已消毒） | `posts.html_cache`，读时零成本 |
| 索引 | 标题/摘要/标签/时间 | SQLite + FTS5 |
| 历史 | 每次保存的版本 | `post_revisions` |

删库不丢文章（md 文件副本 + 备份），`git checkout` 能回滚任何一版——这是选这个形态的可验证收益。

### 8.2 渲染管线（服务端，一次算完）

```
content_md
 → markdown_it.MarkdownIt("commonmark").enable("table").enable("strikethrough")
 → mdit_py_plugins: footnote / tasklists / anchors
 → Pygments 代码高亮（hljs 主题用 CSS 提供，HTML 只带 class）
 → nh3.clean(html, tags=白名单, attributes=白名单, url_schemes={http,https,mailto})
 → 写回 html_cache + 抽取 h2/h3 生成 toc_json
```

**nh3 白名单要点**：

- 允许：`p h1-h4 ul ol li blockquote pre code table thead tbody tr th td a img strong em del hr br figure figcaption span div`
- 属性：`a[href,title,rel]`、`img[src,alt,width,height,loading]`、`code[class]`、`span[class]`（高亮用）
- `iframe` **默认禁止**。若以后要嵌 B站视频，只对 `player.bilibili.com` 单独放行，并强制加 `sandbox="allow-scripts allow-same-origin"`——不要为了一个视频把白名单放大。
- 外链自动补 `rel="noopener noreferrer nofollow"`。

### 8.3 编辑器（站内为主）

| 功能 | 实现 | 阶段 |
|---|---|---|
| 双栏：左写右预览 | CodeMirror 6 + `POST /admin/posts/preview` 防抖 600ms | P4 |
| Frontmatter 表单 | 标题/摘要/标签/封面用独立表单字段，**不写 YAML 头**（少一层解析，减少格式错） | P4 |
| 图片粘贴上传 | CodeMirror `paste` 事件 → `POST /admin/media` → 插入 `![alt](url)` | P4 |
| 自动保存草稿 | 停止输入 5s 或失焦 → `PATCH`，右上角显示「已保存 14:32」 | P4 |
| 快捷键 | `Ctrl/Cmd+S` 保存、`Ctrl/Cmd+Enter` 发布 | P4 |
| 版本历史 | 每次手动保存写一条 revision，侧栏可 diff（先只做"查看+恢复"，diff 后置） | P4 |
| 离开未保存提醒 | `beforeunload` + 路由拦截 | P4 |

### 8.4 阅读体验

- 正文 `max-width: 68ch`，行高 1.75，段落间距 `--space-5`。
- 代码块：横向滚动而非折行；行内代码用 `--font-mono`。
- TOC：宽屏右侧 sticky，窄屏折叠在文首。
- 图片：`loading="lazy"`、写死 `width/height`、点击放大（P5 可选）。
- 每篇页脚：发布时间、标签、上一篇/下一篇。

### 8.5 中文全文搜索（P5 会踩的坑）

SQLite FTS5 默认的 `unicode61` 分词器把**整句中文当成一个 token**——搜「渲染」永远搜不到「Markdown 渲染管线」这句话。三个解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **trigram 分词器（推荐）** | `tokenize='trigram'`，按 3 字符滑窗建索引 | 查询串必须 ≥ 3 字符；2 字的词退化成 `LIKE '%xx%'`（扫表，但个人博客几千行无所谓） |
| 应用层 bigram | 写入前把正文按每 2 个汉字切分插入独立 fts 表 | 多一套写入逻辑，删除/更新要同步 |
| jieba 分词预处理 | 写入前用 jieba 切词、空格连接 | 引入 Python 依赖，词典维护 |

选 trigram：零额外依赖、索引由 SQLite 自己维护、对代码片段和英文同样有效。验收判据：搜「渲染」命中含该词的 3 篇文章，搜 `markdown` 命中英文标题。

## 9. 服务门户与控制台

### 9.1 门户

数据在 `services` 表，展示面 `/` 的门户区读公开接口。

一张卡片：图标、名称、一句话、状态灯、外链/内链。`visible=0` 的服务（内网面板、数据库管理）只在控制台出现——**这是默认值，公开展示必须逐个显式打开**。

### 9.2 控制台三层（严格按层推进）

| 层 | 功能 | 风险 | 阶段 |
|---|---|---|---|
| **L1 只读** | CPU/内存/磁盘/负载/uptime、`systemctl is-active`、`docker ps`、日志尾 200 行 | 极低 | P6 |
| **L2 白名单动作** | 重启指定服务、拉取部署、清缓存、启停指定容器 | 中（但伤害有界） | P7 |
| **L3 任意命令** | 网页里敲 shell | —— | **永不** |

L3 不做是工程判断，不是保守：任意命令框 = 一个 XSS / 一次 session 泄露 / 一次 CSRF 就等于 root；而 L2 的命令和参数都写死在 `actions` 表里，前端只能传动作名，攻击者最多能重复点你已经允许的那个按钮。

### 9.3 动作执行的安全边界

```python
# services/runner.py 的骨架（伪代码，示意边界）
ALLOWED_KINDS = {"systemctl", "deploy", "docker", "script"}

async def run_action(action: Action) -> Result:
    assert action.kind in ALLOWED_KINDS
    argv = build_argv(action)        # 从 DB 拼，参数只来自 args_json
    proc = await asyncio.create_subprocess_exec(
        *argv,                        # 绝不 shell=True
        stdout=PIPE, stderr=PIPE,     # 不接 shell，杜绝注入
        cwd=action.workdir,
    )
    out, err = await asyncio.wait_for(proc.communicate(), timeout=120)
    ...  # 写审计、截断输出到 4KB
```

三条不变量：

1. **`shell=False`**，argv 从 DB 拼，前端不传任何参数。
2. **超时**：120s 强杀，避免部署脚本卡死占住 worker。
3. **审计先写后执行**：先落一条 `ok=NULL` 的记录，执行完更新结果——崩溃时也能看到"有人点了这个按钮"。

### 9.4 监控取数

| 主机 | 取数方式 |
|---|---|
| 计算服务器（API 所在机） | `psutil` 直接读 + `subprocess` 调 `systemctl`/`docker` |
| 存储服务器 | 计算服务器上装一个 10 行的 agent（FastAPI 单文件，`/metrics` 带 token），由 API 拉取 |
| 腾讯云 | 同上，或直接读 `hosts.kind='agent'` 配置的 `/metrics` |

不用 Prometheus + Grafana：三个新服务要维护，收益是"漂亮仪表盘"，而你要的是"点开看一眼就关"。

### 9.5 审计日志

每条 L2 动作写一条：时间、用户、动作名、来源 IP、结果、输出尾部。界面只显示最近 100 条，可筛只失败。

目的不是安全审计，是「我上周到底重启了啥」。

## 11. 视觉与主题

### 11.1 分层（为"以后整体换皮"留的门）

| 层 | 内容 | 换皮时 |
|---|---|---|
| 结构层 | 语义 HTML、DOM 层级、区顺序 | 不动 |
| token 层 | `--bg-*` `--text-*` `--space-*` `--text-*` `--dur-*` | 换值 |
| 皮肤层 | 具体视觉：渐变、玻璃、光晕、3D | 整体替换 |
| 背景层 | `components/background/` | 换实现，调用方不动 |

### 11.2 背景可插拔

```tsx
<SiteBackground variant="nebula" />   // P0：CSS 星云（已在 global.css）
<SiteBackground variant="particles" /> // P1 可选：try/particles.js 的 canvas 版
<SiteBackground variant="sphere" />    // P8：three.js 星球
```

约束三条：

1. 展示区只挂载 `<SiteBackground>`，不关心内部实现。
2. 关掉背景（`prefers-reduced-motion` / 低端设备 / 用户手动关闭）后，站点必须完整可用，文字对比度不变。
3. **WebGL 只用于 Hero、门户页、404**。博客正文页用极简静态背景——沉浸式 3D 背景和长文阅读互相打架，这是绝大多数"炫酷博客"烂尾的原因。

### 11.3 设计 token 规范（P0 已落地雏形）

- 颜色只走语义层（`--text-muted`、`--accent`），组件 CSS 里**禁止出现十六进制色值**。
- 间距只准用 `--space-1..10`（4px 基数）。
- 动效时长只准用 `--dur-fast|base|slow` + `--ease-out`。
- 字阶用 `clamp()`，不给字号写裸 `px`。
- 对比度判据：正文 ≥ 7:1，次要文字 ≥ 4.5:1，禁用 `#666` 这类靠感觉的灰。

### 11.4 动效预算

| 页 | 允许的动效 |
|---|---|
| 展示面 | 滚动进场（IntersectionObserver）、hover 位移 ≤ 4px、背景层动画一个 |
| 博客 | 无入场动画，只保留链接/按钮 hover |
| 控制台 | 只保留状态变化过渡（loading → 数据），不做装饰动画 |

## 13. 安全清单（上线前逐条打勾）

**传输与暴露**

- [ ] 全站 HTTPS，HTTP 301 跳转，HSTS `max-age=31536000`
- [ ] API 只听 WireGuard 地址（`--host 10.8.0.2`），公网无 8000 端口
- [ ] 腾讯云安全组只开 22 / 80 / 443（22 限 IP 或改端口 + 密钥登录 + 禁 root）
- [ ] `/admin` 路由可选加 IP 白名单（Tailscale 或固定出口 IP）

**应用层**

- [ ] 密码 argon2id（不是 bcrypt 默认档、更不是 md5）
- [ ] TOTP 强制开启后才允许访问控制台
- [ ] session token 存库只存 sha256
- [ ] 登录限速 + 账号锁定 + fail2ban
- [ ] 所有状态变更校验 `Origin`
- [ ] 上传：魔数校验 + 白名单 + 大小限制 + 重命名 + 剥 EXIF + **media 目录禁止执行**
- [ ] Markdown 渲染强制 nh3 消毒，`iframe` 默认禁止
- [ ] 全文搜索/列表接口的 `q` 参数走参数化查询（SQLAlchemy 表达式，不拼字符串）
- [ ] `actions` 执行 `shell=False` + 超时 + 审计先写

**响应头**

```nginx
add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; script-src 'self'; frame-ancestors 'none'; base-uri 'self'" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header X-Frame-Options "DENY" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
```

注意：CSP 只在**生产** Nginx 上开，Vite 开发服务器需要内联脚本（HMR），开发环境放开。

**密钥管理**

- 所有密钥在 `api/.env`（`chmod 600`，`git ignore`），`deploy/.env.example` 只放键名。
- 清单：`SECRET_KEY`、`DB_URL`、`STORAGE_ROOT`、`ALLOWED_ORIGINS`、`AGENT_TOKEN_*`、`TOTP_ISSUER`。
- **不得**把数据库密码/token 提交进 git；一旦提交过，视为已泄露，全部轮换。

## 14. 部署与运维

### 14.1 腾讯云（公网入口）

```nginx
server {
  listen 443 ssl http2;
  server_name example.com;

  root /var/www/selfwebsite/dist;
  client_max_body_size 12m;          # 略大于 10MB 上传上限

  location /assets/ {                # 带 hash 的构建产物
    expires 1y;
    add_header Cache-Control "public, immutable";
  }

  location /api/ {
    proxy_pass http://10.8.0.2:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 130s;         # 略大于动作超时
  }

  location /media/ {
    proxy_pass http://10.8.0.2:8000;
    expires 1y;
    add_header Cache-Control "public, immutable";
  }

  location / {
    try_files $uri /index.html;      # SPA 兜底
    add_header Cache-Control "no-cache";
  }
}
```

### 14.2 计算服务器（应用）

| 项 | 做法 |
|---|---|
| 代码位置 | `/srv/selfwebsite`（本地盘，非网络盘） |
| Python 环境 | `uv venv` + `uv pip install -e .`，锁文件入库 |
| 进程管理 | systemd `selfwebsite-api.service`（`Restart=always`, `RestartSec=3`） |
| 数据库 | `/srv/selfwebsite/data/app.db`（本地盘），Alembic 迁移在 `ExecStartPre` 前手动执行 |
| 媒体 | `/mnt/storage/selfwebsite/uploads`（NFS 优先；继续用 CIFS 时注意无 POSIX 权限） |
| 日志 | `journalctl -u selfwebsite-api -f`，同时落 `/var/log/selfwebsite/api.log` 轮转 |
| 监听 | `--host 10.8.0.2 --proxy-headers --forwarded-allow-ips=10.8.0.1` |

### 14.3 WireGuard

- 腾讯云 `wg0: 10.8.0.1/24`，计算服务器 `wg0: 10.8.0.2/24`。
- 只允许 `10.8.0.2:8000` 这一个目标（`AllowedIPs` 收紧），不做全网段互访。
- 配置文件权限 `600`，示例入 git，真文件不入。

### 14.4 上线流程（P2 制定，P2 起固定使用）

```
1. 本地：git push
2. 计算服务器：cd /srv/selfwebsite && git pull
3. api：uv sync && alembic upgrade head && systemctl restart selfwebsite-api
4. 前端：本地 npm run build（或计算服务器构建）→ rsync dist/ 到腾讯云 /var/www/selfwebsite/dist
5. 验证：curl -I https://example.com/  → 200；curl https://example.com/api/healthz → {"ok":true}
```

P4 之后第 2–3 步做成一个 `deploy.sh`，P7 挂到控制台的「拉取部署」动作上——从此点按钮发版。

### 14.5 运维监控（给自己看的）

- `GET /admin/system/info` 一次返回：版本号、DB 大小、挂载点状态、磁盘余量、隧道连通性、上次备份时间。
- 备份失败要在控制台首页亮红——**没人看的告警等于没有告警**。

## 15. 阶段路线

| 阶段 | 交付物 | 主要学到的 | 验收判据 | 估算 |
|---|---|---|---|---|
| **P0** 展示面静态站 | 六区排版 + token 体系 + 动效 | flex/grid、字阶、间距体系、响应式、对比度 | 首屏 JS ≤ 80 kB(gz)（M4-L3 前按 250 kB 算）、Lighthouse ≥ 85/95、无横向滚动 | 2–3 周 |
| **P1** 门户卡片 + 路由 | `react-router` + 展示面门户区（静态配置） | 路由、数据驱动渲染（`map`+`key`）、组件拆分 | 加一个服务只改一个 ts 文件；`/`/`/blog`/`/404` 三路由可跳 | 3–5 天 |

## 17. 为 agent 能力预留的接缝（P9，先只定接口不实现）

目标是明年 agent 全栈实习，这个项目天然适合当练习场。设计上预留三处：

```python
# api/app/services/ai/provider.py
class LLMProvider(Protocol):
    async def complete(self, messages: list[Message], tools: list[Tool] | None) -> Message: ...

# 实现可切换：openai-compatible / 本地 vllm / ollama
```

| 场景 | 读什么 | 写什么 | 人工确认 |
|---|---|---|---|
| 生成文章摘要 | `content_md` | `summary` | 点确认才写入 |
| 解释监控异常 | `metrics` 最近 6h + `journalctl` 尾 200 行 | 无 | — |
| 自然语言查站点 | 只读 API 作为 tools（列文章、查监控、列服务） | 无 | — |
| 运维建议 | 审计日志 + 系统信息 | 无 | — |

**铁律：LLM 只能调用只读 tool。** 任何写操作（发文章、点动作）必须渲染成待确认的表单，由人点。这不是保守，是给未来的自己留一条"AI 出错也不会搞坏生产"的保险。
