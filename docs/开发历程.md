## 2026-11 记录

### 1. 项目不能放在 CIFS 网络盘

**现象**：在 `/rd`（`//192.168.1.112/bluemsunDisk`）上 `npm install` 报 `ENOTSUP: operation not supported, symlink`；`create-vite` 报 `EPERM ... copyFile README.md`。

**原因**：挂载参数 `nounix,file_mode=0777`，CIFS 上 `chmod`、`ln -s`、`fs.copyFileSync` 都不可用。

**正确做法**：项目放本地盘 `/home/justin/code/selfwebsite`。`create-vite` 要在 `/tmp` 生成再 `cp` 回来。

---

### 2. `try/` 里的东西不能当项目依据

**现象**：助手根据 `try/style.css`（深紫 + 粉紫霓虹）推导出一整套主题，被作者否掉。

**原因**：`try/` 是实验区，随时可能是随手试 CSS 属性的地方，与项目无关。

**正确做法**：**任何主题/设计判断都不许引用 `try/`**。真依据是 `docs/主题.md`。

---

### 3. 图像生成的瓶颈不是提示词，是机位

**现象**：用 ChatGPT 生成的书房图，桌子长边斜着、人物侧背对镜头，改提示词改不动。

**原因**：朝向是低频构图属性，由初始噪声与结构条件决定，提示词管不了。

**正确做法**（已在 `try/scene-fix/README.md` 记全）：自己用 3D 摆一个盒子房间，按目标相机参数渲白模 + 深度图，再用 ControlNet-depth 锁死机位。已知天花板：SDXL base 不肯在锁死的格子里画人，人物要单独生成再合成；`img2img` 强度 >0.85 会丢机位、<0.6 上不了色。

---

### 4. 存储服务器能干什么、不能干什么（实测）

**现象**：计划把上传的图片放 `/rd`，但不确定 CIFS 上能否写。

**实测结论**（2026-11-22）：

| 探测 | 结果 |
|---|---|
| `/rd` 根写文件 | ❌ `Permission denied`（服务器端只读） |
| `/rd/Justin/` 建目录、写、重命名、删除 | ✅ 全部可用 |
| `chmod 600` | ❌ `Operation not permitted`，权限恒 777 |
| 20 MB 写入 | 277 MB/s |
| 挂载参数 | `soft`（网络断时快速报错，不会挂死进程） |

**正确做法**：媒体放 `/rd/Justin/selfwebsite/uploads`，文件名随机且写完不改，**上传逻辑不许依赖文件权限**。数据库**永远**放本地盘（WAL 依赖文件锁，跨网络会损坏）。

---

### 5. 文档冻结得太早

**现象**：设计文档 v1.0 刚"冻结"，下一轮讨论就推翻了 5 条结论（多用户、评论、统计、主题、技术栈）。

**原因**：需求没收敛时就冻结，等于把错误固化。

**正确做法**：冻结的前提是议题清单全部收敛。现行机制见 `docs/README.md` 第 5 节"文档纪律"。
